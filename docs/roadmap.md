# Roadmap por Versao

O projeto agora acompanha planejamento de release por versao em arquivos dedicados, em vez de deixar o roadmap solto so em uma lista geral.

## Fluxo oficial

1. copiar o template oficial
2. criar ou atualizar o arquivo da versao
3. preencher objetivo, checklist, entregaveis e links
4. manter issues, PRs, changelog e draft release alinhados com essa versao
5. fechar a checklist antes de tag e release publica

## O que cada roadmap precisa ter

- objetivo da versao
- estado atual
- checklist oficial antes de release
- entregaveis claros
- links para issues, PRs, releases e tags
- notas sobre risco, bloqueios ou escopo adiado

## Como isso conversa com o resto do projeto

- `CHANGELOG.md` continua sendo a fonte oficial do que entrou
- `release-check` valida se versao, changelog e release notes estao alinhados
- `release-status` mostra se Pages, draft release e PyPI estao prontos
- o template de release PR continua sendo o checklist operacional para a promocao de versao
